# Scheme-Intel: 24/7 Cloud Deployment Guide

This guide details how to host Scheme-Intel's Telegram Conversational Gateway on a **free persistent cloud VM** (Oracle Cloud Always Free or GCP Free Tier), enabling 24/7 operation completely independent of your local PC, IDE, or Antigravity sessions.

---

## 1. Architecture Overview

Scheme-Intel uses a decoupled architecture separating scheduled computation from real-time conversational delivery:

```
                            TELEGRAM USER
                                  │
                                  ▼
               ┌─────────────────────────────────────┐
               │   ORACLE CLOUD ALWAYS FREE VM       │
               │   (24/7 Persistent Gateway Daemon)  │
               │                                     │
               │  • Long-polling getUpdates loop     │
               │  • Instant Fast Path (<100ms)       │
               │  • SnapshotSyncer (auto-pulls data) │
               │  • ResearchWorker background thread │
               │  • HTTP Health Probe (:8080)        │
               └──────────────────┬──────────────────┘
                                  │
            Dispatches on complex │ Pulls fresh snapshots
            reasoning queries     │ every 5 minutes
                                  ▼
               ┌─────────────────────────────────────┐
               │          GITHUB ACTIONS             │
               │   (Heavy Computation & Workflows)   │
               │                                     │
               │  • 01 Ingestion (Daily 06:00 IST)   │
               │  • 02 Pipeline & Market Intel       │
               │  • 03 Intelligence Memory Refresh   │
               │  • 04 Telegram Query Dispatch       │
               └─────────────────────────────────────┘
```

### Why this design?
- **Zero Cost Forever**: Runs entirely within Oracle Cloud's Always Free tier (or GCP Free Tier).
- **Your PC Can Be Powered Off**: Polling runs 24/7 on the cloud VM.
- **No Token Hardcoding**: Secrets live strictly in `.env` (chmod 600) on the VM and GitHub Secrets.
- **Self-Healing**: Docker `restart: unless-stopped` and Linux systemd ensure the bot recovers from crashes or VM reboots automatically.
- **Continuous Intelligence Sync**: `SnapshotSyncer` continuously pulls the latest precomputed snapshots generated by GitHub Actions.

## 2. Setting Up an Oracle Cloud Always Free VM (Recommended)

Oracle Cloud Infrastructure (OCI) provides the most generous Always Free tier in cloud computing:
- **Shape Option A (AMD)**: `VM.Standard.E2.1.Micro` (1/8 OCPU, 1 GB RAM) — 2 instances free forever.
- **Shape Option B (Ampere ARM)**: `VM.Standard.A1.Flex` (Up to 4 OCPUs, 24 GB RAM) — completely free.

### Step 1: Create Instance in OCI Console
1. Log in to [Oracle Cloud Console](https://cloud.oracle.com/).
2. Navigate to **Compute** > **Instances** > **Create Instance**.
3. **Name**: `scheme-intel-gateway`.
4. **Placement**: Select default Availability Domain.
5. **Image**: Select **Canonical Ubuntu 24.04** or **Ubuntu 22.04 Minimal**.
6. **Shape**:
   - Select **Ampere (ARM)** `VM.Standard.A1.Flex` (1 OCPU, 6 GB RAM) OR
   - Select **Specialty and legacy** > `VM.Standard.E2.1.Micro` (1 OCPU, 1 GB RAM).
7. **Networking**:
   - Create new Virtual Cloud Network (VCN) and public subnet.
   - Ensure **Assign a public IPv4 address** is checked.
8. **SSH Keys**:
   - Download the generated private key (`ssh-key-*.key`) or paste your existing public SSH key (`~/.ssh/id_rsa.pub`).
9. Click **Create** (the VM will be running in ~60 seconds).

### Step 2: Open Ingress Ports (Firewall)
In the OCI Console:
1. Click your instance's subnet (e.g. `subnet-...`).
2. Click **Default Security List**.
3. Under **Ingress Rules**, click **Add Ingress Rules**:
   - **Source CIDR**: `0.0.0.0/0`
   - **IP Protocol**: TCP
   - **Destination Port Range**: `22` (SSH - usually present by default)
4. (Optional) For external health monitoring:
   - Add another rule for TCP port `8080`.

## 4. Deploying Scheme-Intel on the VM

### Step 1: Connect to the Cloud VM
From your local terminal (PowerShell, macOS, or Linux):
```bash
ssh -i /path/to/your-private-key.key ubuntu@<YOUR_VM_PUBLIC_IP>
```

### Step 2: Clone the Repository
```bash
git clone https://github.com/botv99/scheme-intel.git
cd scheme-intel
```

### Step 3: Configure Environment Secrets
Copy the environment template:
```bash
cp .env.example .env
chmod 600 .env
nano .env
```
Fill in your production credentials:
```env
TELEGRAM_BOT_TOKEN=123456789:ABCdefGhIJKlmNoPQRsTUVwxyZ
TELEGRAM_CHAT_ID=5917850553
TELEGRAM_DELETE_WEBHOOK=true
GITHUB_TOKEN=ghp_yourPersonalAccessTokenHere
GITHUB_REPOSITORY=botv99/scheme-intel
PORT=8080
```
> [!IMPORTANT]
> - `TELEGRAM_BOT_TOKEN`: Your new bot token from `@BotFather`.
> - `GITHUB_TOKEN`: A GitHub Personal Access Token (classic with `repo` scope, or fine-grained with `Actions: write`) so the VM can trigger the `04-telegram-query.yml` workflow when users ask complex multi-step questions.
> - Never commit `.env` to git (it is included in `.gitignore`).

### Step 4: Run the Automated Deploy Script
Execute the turnkey bootstrap script:
```bash
chmod +x deploy/oracle/deploy.sh
./deploy/oracle/deploy.sh
```
This automated script:
1. Installs Docker and Docker Compose plugin.
2. Creates persistent directories (`data/`, `logs/`).
3. Builds the production container.
4. Starts the service with `restart: unless-stopped`.
5. Registers and enables `scheme-intel.service` in systemd for boot autostart.
6. Runs an instant health check probe.

## 6. Daily Operations & Zero Maintenance

### How to Update to the Latest Code
When you push new features or fixes to GitHub:
```bash
cd ~/scheme-intel
chmod +x deploy/oracle/update.sh
./deploy/oracle/update.sh
```

### How Log Rotation Works
Docker is configured in `docker-compose.yml` to automatically rotate logs:
- Maximum log size: `10 MB`
- Maximum log files: `3`
The VM disk will never fill up from container logs.

### Systemd Service Management
The gateway is registered as a system service. If the VM reboots (e.g. cloud provider host maintenance), systemd automatically brings the gateway back up:
```bash
# Check service status
sudo systemctl status scheme-intel.service

# Restart service
sudo systemctl restart scheme-intel.service

# Stop service
sudo systemctl stop scheme-intel.service
```

## 7. Troubleshooting

| Symptom | Cause | Solution |
| :--- | :--- | :--- |
| `getUpdates returned HTTP 409 Conflict` | Another poller instance is running or webhook is active | Ensure local PC bot is stopped. Verify `TELEGRAM_DELETE_WEBHOOK=true` in `.env`. |
| `TELEGRAM_BOT_TOKEN is not configured` | Missing or unreadable `.env` file | Check `cat .env`. Verify permissions (`chmod 600 .env`). |
| Health check shows `Snapshot is missing` | Initial snapshot hasn't synced yet | The `SnapshotSyncer` will auto-fetch within 5 minutes, or run `python -m scheme_intel.intelligence_memory.refresh`. |
| Permission denied on `data/` | User/UID mismatch | Run `sudo chown -R 1000:1000 data logs` on the host. |
